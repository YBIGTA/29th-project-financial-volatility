## 만든 코드 구성

```bash
pip install -r requirements.txt
cd src
python run_all.py             # 전체 실행 (시세 -> 뉴스/게시판 전소스 -> 전처리)
# 개별로 돌릴 때
python crawl_price.py         # 일봉 시세 (4종목 + KOSPI/KOSDAQ/VIX)
python crawl_news.py          # 네이버 뉴스
python crawl_board.py         # 네이버 종목토론방
python crawl_paxnet_board.py  # 팍스넷 종목토론방
python crawl_edaily_news.py   # 이데일리 증권뉴스 (본문까지 포함)
python crawl_toss_community.py # 토스증권 커뮤니티
python preprocess.py          # 텍스트 정제
python sentiment_score.py     # 감성점수 산출 + 장중/장외 지수화 (--aggregate-only로 집계만 재실행 가능)
python build_summary.py       # 종목별 merged_daily.csv + 차트 생성 (data/정리)
```

네이버 뉴스·게시판은 한 번에 페이지 100개(2,000건)까지만 가져올 수 있는 제한이 있습니다. 삼성전자·SK하이닉스처럼 게시량이 많은 종목은 하루만 지나도 그날 글이 밀려나서 가져오지 못합니다. 그래서 매일 실행해야 실제 보유 기간이 늘어나도록 만들었습니다. 팍스넷·이데일리는 그런 제한이 없어서 실행할 때마다 3개월치를 다시 수집합니다.

## 네이버 소급 기간의 한계

네이버 뉴스·게시판은 페이지당 20건 × 최대 100페이지(약 2,000건) 상한이 있어서, 게시량이 많은 삼성전자·SK하이닉스는 실제로는 최근 며칠치밖에 확보되지 않습니다. 이 상한은 기간이 아니라 건수 기준이라, 크롤링 대상 기간을 늘려도 더 가져와지지 않습니다. 대신 삼성전자·SK하이닉스는 팍스넷·이데일리가 이미 3개월 전체를 커버하고 있어서, 네이버 쪽 데이터는 최근 스냅샷 정도로 보고 있습니다.

### 보완용: 네이버 통합검색 날짜 슬라이싱 (`crawl_naver_search_news.py`, 직접 실행 필요)

네이버 뉴스 API의 2,000건 상한은 "검색 쿼리 1회" 기준이라, 날짜 범위를 하루 단위로 잘게 쪼개서 여러 번 검색하면 하루치가 2,000건을 넘지 않는 한 우회됩니다(`search.naver.com`이 `ds`·`de` 날짜 파라미터를 지원하는 걸 실측으로 확인). 다만 이 사이트는 robots.txt가 모든 봇을 막고 있어서(`Disallow: /`), 이 스크립트는 자동 파이프라인(`run_all.py`)에는 넣지 않았고 직접 실행해야 합니다.

예전 종목뉴스 API도 2,000건 상한을 다 못 채우고 실제로는 6일치 정도에서 끝났던 걸 감안해서, 하루에 다 긁으려 하지 않고 하루 3페이지(30건)만 표본으로 가져오도록 줄였습니다 — 요청 총량이 줄어야 IP 차단 위험도 낮아지고, 그래야 90일 전체를 고르게 훑을 수 있습니다. 요청 간격도 1.5~3.5초 사이에서 매번 무작위로 흔들리게 해뒀습니다(똑같은 간격도 그 자체로 봇 패턴이라).

막히면(위 에러) 완전히 멈추지 않고 20분 쉬었다가 자동으로 재시도합니다(최대 6번, 총 2시간). 재시도할 때는 이미 저장된 날짜는 건너뛰고 안 받은 날짜만 이어서 받아서, 재실행할 때마다 처음부터 다시 긁지 않습니다. 자기 전에 실행해두고 자면 됩니다.

```bash
cd src
python crawl_naver_search_news.py
python preprocess.py   # news_search_{종목}_clean.csv까지 같이 정제됨
```

절대 시각이 화면에 안 나오고 "N시간 전" 상대시각만 나와서, 시간 단위 정밀도는 없고 날짜 단위로만 채워집니다(그날 정오로 기록). `headline1`/`body1` 클래스명으로 파싱하는데, 네이버가 프론트엔드를 바꾸면 깨질 수 있습니다 — 실행했는데 계속 0건만 나오면 그것부터 의심해볼 것.

## 보완용: 매일경제 증권 RSS (`crawl_mk_news.py`, 직접 실행 필요)

중간발표 피드백 중 "이데일리 단일 뉴스 소스의 정치적 편향" 지적이 있었습니다. 실제로 찾아보니 이데일리는 진보 성향으로 분류되는 경제지라, 반대 성향(우파/중도우파) 경제지를 하나 더 넣어서 완화하려고 했습니다.

후보를 세 곳 확인했는데 둘은 접근 자체가 안 됐습니다 — **한국경제**(robots.txt는 허용이지만 Cloudflare 봇 차단), **조선비즈**(기사 목록을 JS로 나중에 그려주는 방식이라 일반 요청으론 안 보임). **매일경제**만 남았는데, 여긴 페이지 접근은 되지만 robots.txt가 ClaudeBot을 이름으로 명시해서 막아뒀습니다(`User-agent: ClaudeBot / Disallow: /`, `User-agent: *`는 허용). 그래서 이 스크립트도 네이버 통합검색과 같은 이유로 자동 파이프라인에 넣지 않고 직접 실행해야 합니다.

```bash
cd src
python crawl_mk_news.py
python preprocess.py   # mk_news_{종목}_clean.csv까지 같이 정제됨
```

RSS(`rss/30000001`, 증권 섹션) 기반이라 **최신 기사 몇십 건 정도만** 나옵니다 — 이데일리처럼 6개월 전체를 날짜별로 훑는 구조가 아니라 네이버 뉴스 API 같은 "최근 스냅샷" 소스입니다. 여러 번 실행하면 news_id 기준으로 누적됩니다. 6개월 전체가 필요하면 매일경제의 날짜 범위 검색 URL을 찾아서 확장해야 하는데, robots.txt 때문에 제가 직접 사이트를 열어서 확인은 못 했습니다.

**아직 안 한 것**: `sentiment_score.py`의 `collect_all_text()`에 이 소스를 아직 안 넣었습니다 — 그 파일은 승곤님 담당이라 임의로 안 건드렸습니다. 이 참에 "뉴스 소스 여러 개 vs 커뮤니티 소스 여러 개 가중치를 어떻게 줄지"도 같이 정리하면 좋을 것 같습니다(지금은 소스별 건수 그대로 다 섞어서 평균 내다보니 토스 비중이 압도적임).

## 토스증권 커뮤니티 — 시간대 표본 수집

화면에는 글 목록이 바로 보이지 않지만, 실제로는 로그인 없이 열려있는 내부 API가 있습니다.

```
GET https://wts-cert-api.tossinvest.com/api/v4/comments
    ?subjectType=STOCK&subjectId={ISIN}&commentSortType=RECENT&lastCommentId={cursor}
```

- `subjectId`는 종목코드가 아니라 ISIN을 사용합니다 (코드↔ISIN 매핑은 `crawl_toss_community.py`의 `ISIN` 딕셔너리).
- 페이지당 11건 고정이고, 다음 페이지는 마지막 댓글의 `commentId`를 `lastCommentId`로 넘기면 됩니다.
- `commentId`는 전 종목이 공유하는 전역 순번이라 시간과 거의 선형 비례합니다 — 즉 임의의 오래된 `lastCommentId`를 넣으면 그 근처 시점 댓글로 바로 점프됩니다.

삼성전자·SK하이닉스는 댓글 속도가 너무 빨라서(3개월 전체를 순차 페이지네이션으로 모으려면 요청이 9만 건 이상 필요) 위 점프 기능으로 하루 안 장중 3곳·장외 4곳씩 고정 시각을 정해 표본을 추출합니다(`crawl_comments_sampled`). 카카오·에코프로비엠은 댓글이 적어서 기존 순차 수집(`crawl_comments`)만으로 3개월이 채워집니다. 전처리 단계에서 추천 0건인 댓글은 노이즈로 보고 제외했습니다(`preprocess.MIN_TOSS_LIKES`).

## 감성분석

- 모델은 `snunlp/KR-FinBert-SC`를 사전학습 그대로 사용했습니다 (파인튜닝은 하지 않았습니다).
- 이데일리 뉴스만 쓰면 카카오·에코프로비엠은 하루 기사 수가 너무 적어서 결과가 듬성듬성해지기 때문에, 위 5개 소스를 전부 합쳐서 스코어링합니다.
- 일별 하나로 뭉치지 않고 실제 거래일 기준으로 **장중(intraday, 09:00~15:30 게시물)**과 **장외(overnight, 전 거래일 15:30 이후~해당 거래일 09:00 이전 게시물)**를 나눠서 지수화합니다. 주말·공휴일 게시물은 가장 가까운 다음 거래일의 장외 감성에 포함됩니다.
- 게시물이 없는 구간은 감성지수를 `0`으로 채우되 `no_posts=1`을 같이 기록해서, 실제 중립 감성(`sentiment_index=0, no_posts=0`)과 정보 부재를 구분할 수 있게 했습니다.
- `sentiment_score.py --aggregate-only`로 모델을 다시 돌리지 않고 집계만 갱신할 수 있습니다.
- `build_summary.py`가 감성지수와 시세를 합쳐 종목별 `data/정리/{영문종목명}/merged_daily.csv`와 차트 5종(장중/장외 감성, 종가, 캔들스틱, 감성·종가 비교)을 만듭니다.

## 아직 못 한 것

- 네이버·팍스넷 게시판 본문 전체는 JS 렌더링이라 가져오지 못했습니다. 지금은 제목만 있습니다.
- 네이버 오픈 API(뉴스/블로그/카페 공식 검색)는 Client ID/Secret을 발급받으면 추가할 수 있는데, 검토 결과 검색당 상한이 지금 쓰는 방식보다 낮아서(1,000건) 실익이 적다고 판단해 보류했습니다.
- 게시판·커뮤니티 데이터에는 닉네임, 자극적 표현이 섞여있습니다. 발표자료·대시보드에는 원문을 그대로 쓰지 않고 필요하면 익명 처리해서 쓸 계획입니다.
