## 1. 타겟(예측 대상)

**다음날(t+1)의 실현변동성**

```
log_ret = log(오늘종가 / 어제종가)
realized_vol = log_ret의 5일 이동표준편차   # "최근 며칠간 얼마나 출렁였는가"
target_vol[t] = realized_vol[t+1]           # 오늘(t) 시점에서 "내일"을 맞추는 문제로 설정
```

## 2. 피처(입력 변수)

| 카테고리 | 피처 | 용도 |
|---|---|---|
| 자기 과거 정보 | `realized_vol_lag1~3`, `log_ret_lag1` | 변동성의 "관성"(어제와 비슷하게 유지되려는 경향) 반영. GARCH는 모델 구조 자체가 이 정보를 내장하고 있어서 별도로 안 넣어도 됨 (XGBoost만 필요) |
| 시장 배경 정보 | `vkospi_close`, `vkospi_lag1`, `kospi_ret`, `kosdaq_ret` | 개별 종목 변동성은 시장 전체 분위기 영향을 받으므로, 이걸 통제해야 "감성지수만의 순수 기여도"를 볼 수 있음 |
| 감성지수 (핵심 검증 대상) | `sentiment_intraday`, `sentiment_overnight` | 우리가 실제로 검증하려는 재료 |

**팀 합의 필요**: item_count(게시글수)를 추가할 것인지에 대한 논의 필요

### 감성지수 시점(shift) 처리

```
[t일 장중]──[t일 마감]──[t일 마감~t+1일 개장, 장외]──[t+1일 개장]
  intraday[t]              overnight[t]                target_vol[t] 시작
```

`intraday[t]`, `overnight[t]` 둘 다 `t+1`일이 시작되기 전에 이미 확정된 정보라서, **shift 없이 t행 그대로 사용**. (타겟이 "다음날 하나"뿐이라 이렇게 정리됨. 만약 나중에 "당일 변동성"까지 별도로 예측하게 되면 그때는 shift 로직을 다시 짜야 함.)

## 3. 4개 모델 구조

| 모델 | 감성지수 | 하이퍼파라미터 |
|---|---|---|
| GARCH(1,1) | 없음 | 튜닝 없음, 표준값 고정 |
| GARCH-X | 있음 | 튜닝 없음, 표준값 고정 |
| XGBoost base | 없음 | 별도 튜닝 (다음 단계) |
| XGBoost +sentiment | 있음 | 별도 튜닝 (다음 단계, base와 같은 절차·탐색범위·평가지표로 각자 최선의 값 탐색) |

**핵심 질문**: "감성지수를 넣었을 때 안 넣었을 때보다 확실히 더 잘 맞추는가?" (GARCH 쌍, XGBoost 쌍 각각에서 검증)

## 4. GARCH-X 구현 방식 (중요 - arch 패키지 한계 때문에 표준 방식과 다름)

원래 GARCH-X는 "분산방정식(변동성 계산식) 안에 외생변수(감성지수)를 직접 추가"하는 모델. 하지만 파이썬 `arch` 패키지는 이 기능을 기본 지원하지 않음(`x=` 옵션이 분산방정식이 아니라 평균방정식용).

**대안: 2단계 회귀(encompassing regression) + walk-forward**
1. GARCH(1,1)을 **매 시점마다 그 이전 데이터로만 다시 fit**해서 one-step-ahead 조건부변동성 예측 (walk-forward, 데이터 누수 없음)
2. `target_vol ~ garch_vol + sentiment_intraday + sentiment_overnight` 로 OLS 회귀 (train_val 구간에서 학습)
3. 감성지수 계수의 p-value로 유의성 판단, 회귀계수는 홀드아웃에 그대로 적용해 최종 평가

같은 연구질문(감성지수의 추가 설명력)에 답하는 표준적인 대안 방법이며, 실제 학술 연구에서도 새 지표의 정보 가치를 검증할 때 자주 쓰는 방식.

**팀 합의 필요**: 이 방식을 "GARCH-X"라고 부를지, "GARCH forecast + sentiment 회귀"라는 별도 명칭으로 부를지 확정 필요.

## 5. Walk-forward Validation

### 왜 쓰는가
일반적인 "한 번 train/test 나누고 끝"이 아니라, **매일 실제로 예측을 반복하는 상황을 그대로 시뮬레이션**하는 방법. 시간이 하루씩 지날 때마다 "그 시점까지 알 수 있었던 정보로만" 다시 학습하고 바로 다음날을 예측 → 반복.

```
Day 1~N 학습 → Day N+1 예측 → 실제값과 비교
Day 1~N+1 학습 → Day N+2 예측 → 실제값과 비교
... (반복)
```

### 데이터 분할 구조

```
전체 데이터
 ├── [A] train_val 구간 (앞부분, 지금은 마지막 8일 제외한 전부)
 │     └── 이 안에서 walk-forward 반복 → (다음 단계) 여러 하이퍼파라미터 후보를 비교해 최적값 선정
 └── [B] holdout 구간 (마지막 8일)
       └── 튜닝 과정에서 절대 사용하지 않고, 최종 선정된 모델을 "한 번도 안 본 데이터"로 딱 한 번만 평가
```

[A]는 "모의고사를 여러 번 보며 공부법을 찾는 구간", [B]는 "그 공부법으로 딱 한 번 보는 진짜 시험"에 비유 가능. [B]를 튜닝 중에 들여다보면 성능이 실제보다 좋아 보이는 착시가 생기므로 반드시 분리.

### 평가지표는 어떻게 계산되나
Walk-forward로 나온 여러 번의 "실제값-예측값" 오차를 전부 모아서 RMSE(오차 제곱의 평균에 루트), QLIKE(변동성 예측 전용 손실함수)를 계산 → **여러 날짜의 예측 결과를 종합한 평균적인 성능**을 하나의 숫자로 나타낸 것.

### 최종 모델 선정 방식 (다음 단계에서 진행)
1. [A] 구간에서 여러 하이퍼파라미터 조합마다 walk-forward를 돌려 평균 RMSE/QLIKE 비교
2. 평균 성능이 가장 좋은 조합을 최종 하이퍼파라미터로 채택
3. 그 설정값으로 [A] 전체를 한 번에 재학습 → [B](holdout)로 딱 한 번 최종 평가

## 8. 4종목 홀드아웃 결과 스냅샷 (v3, 튜닝 전 참고용)

| 종목 | GARCH(1,1) RMSE | GARCH-X RMSE | XGBoost base RMSE | XGBoost +sentiment RMSE |
|---|---|---|---|---|
| 삼성전자 | 0.0514 | 0.0772 | 0.0304 | 0.0305 |
| SK하이닉스 | 0.0697 | 0.0473 | 0.0326 | 0.0321 |
| 카카오 | 0.0101 | 0.0103 | 0.0093 | 0.0089 |
| 에코프로비엠 | 0.0245 | 0.0226 | 0.0093 | 0.0075 |

**해석 시 주의**: 종목마다 감성지수 포함 여부의 유불리가 다르게 나타남 (에코프로비엠·카카오는 개선, 삼성전자는 거의 동일, 등). 홀드아웃이 종목당 8일뿐이고 튜닝 전이라 지금 숫자로 "어떤 종목엔 도움되고 어떤 종목엔 안 된다"는 결론을 내리기엔 이름. 튜닝 + Diebold-Mariano test 이후 재해석 필요.
